# ofc-earthquake · 自组织临界与古腾堡–里特定律

> 12 月主题「临界现象 · 相变」第 4 件。用 OFC（Olami–Feder–Christensen）弹簧-块体模型在浏览器里跑一片会自组织到临界的断层面，数出它的**古腾堡–里特 b 值**——也就是真实地震目录里那条著名的 `log N = a − b·M`。

单文件、零依赖、离线可跑：直接双击 `index.html`。

## 一、为什么做这个

前三个作品（kuramoto-sync / ising-domains / percolation-threshold）分别讲了同步、序参量与渗流阈值，都是「系统在参数逼近某个点时突然变样」。但 SOC（自组织临界）是另一类：**不需要调参数，系统自己走到临界点**。砂堆自己堆成那个会崩的斜面，断层自己把自己顶到「随时会滑但谁也说不准哪一下最大」的状态。

b 值是最值得直接呈现的可测量：它把「多少次小地震 / 多少次大地震」压成一个数，真实构造地震目录约 0.8–1.2，而简单物理模型给出更低的值——这个落差本身就是一件值得展示的事。

另外想做的是把「临界」从抽象概念变成可交互的手感：亲手往稳定场里推一格，看一个针尖大的扰动能滚成多大的雪崩。

## 二、核心机制与技术点

**物理模型（OFC，二维 L×L 四连通）**

每格一根弹簧，力 `F ∈ [0,1]`，`F=1` 为滑动阈值。每一步整片格子均匀注入 `v`（`v ≪ 1`，等效无限慢的板块拖拽），任一格超阈值就**整根泄掉**：自身清零，存在的每个邻居各得 `α·F_old/4`。`α ∈ (0,1]` 是守恒参数，`(1−α)` 及部分边界损失构成耗散。

两个建模要点是实测出来的，不是查来的：

1. **滑动必须清零，不能「压回阈值 1」**。若只释放超出量 `d=F−1` 而保留 1，每格会永远贴在阈值上，任何扰动瞬间传遍全格——退化极限环，实测最大规模恒等于 `N`、`b≈0`，没有任何尺度分离。清零让应力场有深有浅，级联才会在局部终止。
2. **必须二维**。一维链的级联随链长指数衰减，拿不到无标度分布。

**实现**

- `Float64Array` 力场 + `Int32Array` 松弛栈 + `Uint8Array` 标记数组；`marked.fill(0)` 每轮重扫，保证 O(N)。
- 松弛写成「扫描所有超阈值格 → 松弛一轮」的外循环，直到没有超阈值格（上限 64 轮兜底浮点残差）。
- 能量账目精确闭合：耗散按**实际分配量**计算（边界格邻居不足 4 个，差额也计入耗散），实测 `输入 = 初始现存 + 注入 − 耗散` 误差 < 1e-9。
- b 值来自对 `log₂` 分桶**累计频次**的最小二乘回归（对大小事件都公平，不会像密度直方图那样被小事件噪声主导），并与 `b=1` 的真实地震参考线同图对比。
- 确定性 PRNG（mulberry32），同种子复现；渲染用像素化 canvas，雪崩时高亮受影响格并渐隐。

## 三、怎么玩

- **跑起来**：打开页面即自动加载，格子颜色越亮应力越高。约 1/v 步后开始出现零星小地震，之后进入「大石头带小石子」的 SOC 状态。
- **触发主震**（空格或按钮）：把当前最紧张的格推过阈值，制造一次确定性触发，看它能滚多大。
- **动手推**：点击画布往该格注水，`Shift+点击`把它挖低——这是感受「针尖扰动 → 大雪崩」最直接的方式。
- **调节**：耗散 `1−α` 越大，系统越「湿」，最大雪崩越小；加载速率 v 理论上不该改变 b（这就是 SOC），可以亲自验证这条不变性。
- **读图**：右下是对数坐标的累积频次曲线，斜率就是 b；叠加的虚线是真实地震目录的 `b=1`。左侧能量一栏核对 `输入 / 耗散 / 现存`，误差应远小于 1%。
- **批量**：「跑 2000 次地震」用 setTimeout 分片跑完，统计面板实时刷新进度。

快捷键：`空格` 主震 · `P` 暂停 · `D` 震后重记 · `R` 重置 · `点击` 注水 · `Shift+点击` 挖低。
