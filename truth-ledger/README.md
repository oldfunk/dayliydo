# 真相账本 · Truth Ledger

一个纯离线的单文件推理台。五个人的证词，一张可以推演的矩阵——你自己当法官。

## 一、为什么做这个（设计意图）

已有的推理小游戏几乎都是「点击找线索 → 弹出真相」的脚本式流程：玩家在猜作者的思路，而不是在推理。本作想做一件更难、也更有意思的事：**把推理过程本身变成一个可操作的对象**。

它借的是推理小说里的经典结构——罗生门式多重叙述。五个人各说了一段话，**没有一个人说全了实话，但也没有一个人在整件事上撒谎**。每个人隐瞒的动机不同：跑堂隐瞒作案，女伶隐瞒私会，行商隐瞒赌钱，道士隐瞒躲债，只有养女说了全部真话。

关键设计判断：**不告诉玩家谁在撒谎，只让玩家自己下裁定，然后看见谁跟自己对不上。** 游戏不提供"这是线索"的提示，提供的是推演工具。

一句话概括它巧在哪：**每个角色的真话／假话不是散点，而是由"每句命题上取严格多数"这一条规则统一生成的**——所以只要玩家把每条命题判对，冲突就会自然聚集到真凶身上；判错一条关键命题，热力就会指向无辜的人。玩家的推理质量直接、可见地改变结论。

## 二、核心机制 / 技术点

### 1. 证词矩阵与严格多数约束

- 9 条命题 × 5 位陈述者 = 45 个格子。每个格子是三态：`1` 称其为真、`0` 称其为假、`-1` 未提及。
- 每条命题的**真相**不是手写的，而是由"在提到它的陈述者中取严格多数"推出来的。数据里显式写了一份 `truth`，并有一致性校验保证它恰好等于多数决结果——没有平票（9 条命题的真/假票数分别是 4:0、4:0、2:1、1:4、1:2、1:3、4:0、3:0、3:2）。
- 这条规则是整个谜题可解的根基：**每个撒谎者只需要在"对自己不利"的少数命题上说假话，就足以让多数仍然指向真相。**

### 2. 玩家裁定驱动的矛盾热力

- 玩家对每条命题下「真 / 假 / 未定」裁定，格子立刻变色：与自己裁定一致的证词亮绿，冲突的亮红。
- 右侧「矛盾热力」按裁定实时排序，排序键是 `关键命题冲突数 → 总冲突数 → 发言量`。
- **这是本作最重要的一点**：热力是**玩家自己的裁定**算出来的，不是真相算出来的。裁定对了，热力指向真凶；把关键命题 f3（窗下脚印）误判为假，第一名立刻变成行商胡铁山。工具会如实地放大你的错误。

### 3. 关键命题与计分

- 三条「关键命题」（窗下脚印、账本缺页、后巷翻窗）直接指向密室如何被伪造。
- 满分 6 分 = 关键命题 3 + 凶手 2 + 动机 1。结局称号四档：明镜高悬 / 抽丝剥茧 / 雾里看花 / 被人牵着走。
- 结案后给出：凶手与手法、真实动机、关键命题逐条核对、七段时间线重构、以及**五位陈述者各自的隐瞒**——把"每个人为什么撒谎"讲清楚，而不是只报一个名字。

### 4. 真相码：把推理过程本身变成可分享的文本

- 全部状态压缩成 `TL1.<base64url>`：9 条裁定的三态 + 指认的凶手 + 动机。
- 导入端做严格校验：前缀必须是 `TL1.`、必须能 base64 解码、必须是合法 JSON、`v` 必须为 1、裁定数组长度必须恰好等于命题数、每一项必须是 0/1/2、凶手与动机必须是已知 id——任何一项不符即拒绝并提示。
- 因为只存**裁定**而不存结论，真相码天然是"推理中途存档"：别人粘贴进去，就站在你停下的地方接着推。
- 编码只含 base64url 安全字符，无空格、无引号、无非 ASCII，可以直接贴进任何聊天窗口。

### 5. 安全与零依赖

- 单个 `index.html`，无 CDN、无网络请求、无构建步骤、无 ES module（避开 `file://` 下的 CORS 限制）。
- **全文件零 `innerHTML` 赋值**：所有 DOM 都通过 `createElement` + `textContent` + `createTextNode` 构建，因此不存在注入面。导入的真相码只被解析成布尔与已知 id，从不作为字符串写入 DOM。
- 无 `eval` / `new Function` / `document.write` / 动态 `import`。
- 进度存在 `localStorage`，损坏数据静默丢弃，隐私模式下静默失败不报错。

## 三、怎么玩

1. 双击 `index.html`。先展开顶部的「案卷」读案情。
2. 从第一行开始，把每条命题判为「真」或「假」。判完一条，那一行的五个格子立刻标出谁跟你对不上。
3. 点击任意格子，下方显示该人的原话，并告诉你这条证词与你的裁定是一致还是冲突。
4. 盯着右侧「矛盾热力」。冲突集中在**关键命题**上的人最可疑——但热力只反映你的裁定，别把自己的偏见当证据。
5. 三条关键命题都判完，在「结案」里指认凶手和动机，提交。
6. 看完真相重构后，用「真相码」把推理过程存档或发给别人；对方用「导入真相码」就能复现你的全部裁定。

快捷键：`Esc` 关闭结案弹层。进度自动保存，关掉浏览器再打开还在。

## 四、验证记录

开发时用临时脚本实际跑过（Node + 迷你 DOM 垫片，非人工目测），共 47 项断言全部通过：

- **逻辑层**：结构完整性、证词合法性与命题引用、9 条命题的多数决约束、凶手在关键命题上的唯一性、热力排序第一名、凶手对关键命题的覆盖。
- **执行层**：真实执行页面脚本，模拟点击全部 27 个裁定按钮、提交拦截、正确结案、真相码生成与回灌、6 种非法真相码注入、localStorage 写入。
- **安全层**：源码级断言无 `innerHTML` / `eval` / `new Function` / `document.write` / 动态 `import` / `http(s)` 链接 / 网络调用 / CDN / 追踪 / IP / 邮箱 / 本地路径。

过程中发现并修复了两个真实缺陷：

1. **裁定按钮写错命题**：点击回调闭包捕获了外层循环变量 `f`，导致 27 个按钮全部写入最后一条命题的裁定。修复方式是把 `f.id` 作为参数传入 IIFE 固定下来。回归断言专门覆盖这一点——点 f1 的「真」只应写入 `{f1:1}`。
2. **非法真相码被静默降级**：导入端遇到未知的凶手/动机 id 时，原先会悄悄丢弃该字段并照常导入，与「严格校验」的设计声明不符，且会静默丢失玩家数据。修复后：`w`/`m` 允许为空串（尚未指认），但一旦非空就必须是已知 id，否则整份真相码拒绝。

垫片只实现了页面实际用到的 DOM 子集，验证的是逻辑、状态流与安全属性，**不代表真实浏览器的视觉与布局效果**。
